# Telemetry Reporting Cadence (v1)

Status: active workflow  
Last updated: 2026-05-24

## Purpose

Define the minimum weekly operating rhythm for turning local opt-in telemetry exports into decision-ready S+ signals.

## Inputs

- Per-user shareable reports generated by `grapheme telemetry export --json`
- Stored as JSON files under a weekly folder (example: `.grapheme/telemetry/reports/2026-W21/`)

## Weekly Workflow

1. Collect redacted reports into one directory.
2. Run weekly rollup script.
3. Publish a short summary in quality/release notes.
4. Feed top blockers into roadmap checklist updates.

### Rollup Command

```bash
scripts/telemetry-weekly-rollup.sh .grapheme/telemetry/reports/2026-W21 \
  --out docs/quality/weekly-telemetry-2026-W21.md
```

Without `--out`, the rollup prints markdown to stdout.

## Output Contract

The rollup produces a concise markdown summary with:

- coverage: report count, events, command results, success rate, avg duration
- TTFS funnel: starts, successes, failures, success rate
- top failure stages
- top error classes
- top commands

## Interpretation Rules

- TTFS success rate below target from `docs/quality/splus-metrics.md` is a P1 DX signal.
- A dominant failure stage indicates where onboarding should be rewritten first.
- Repeated top error class over multiple weeks should become a troubleshooting or CLI UX fix ticket.
- Sustained drop in command success rate should trigger runtime/compiler regression check.

## Scenario Feedback Loop

Use `docs/quality/scenario-playbooks-v1.md` as the default post-onboarding scenario set.

Weekly linkage:

1. Map top failure stages to scenario owners:
  - `policy` -> update policy preflight/setup sections in scenario playbooks.
  - `runtime` -> add troubleshooting notes and example caveats.
  - `parse`/`args` -> improve command snippets and expected outputs.
2. Pick one scenario playbook update per week based on dominant failure signal.
3. Record the linked docs change in roadmap execution updates.

This keeps telemetry signals tied directly to scenario-first learning depth improvements.

## Roles

- Product owner: owns weekly interpretation and ROI prioritization.
- DX/docs owner: owns onboarding and troubleshooting updates from findings.
- Runtime/tooling owner: owns defect and guardrail follow-ups.

## Exit Criteria (v1)

The cadence is considered operational when:

1. Weekly rollup runs for at least 3 consecutive weeks.
2. At least one roadmap or docs update is linked to each weekly rollup.
3. TTFS and top failure stage are reviewed in weekly planning.
