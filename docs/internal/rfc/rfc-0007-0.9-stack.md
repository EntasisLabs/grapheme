## PR #42 — view `if` / `for` (landed)

View element bodies accept conditional and repeated children. Compile-time View IR (`grapheme-ui/2`) keeps `$if` / `$for` nodes; the headless session expands them when rendering (false `if` branches omitted; `for` rows under `…/$for/<key>/…`; `$post` / `$post.field` in props and binding args). Expanded snapshots stay `grapheme-ui/1`.

```grapheme
view FeedView on Feed {
  Column {
    if $status == "pending" { Text("Loading…") }
    if $status == "ready" {
      for $post in $posts key $post.id {
        Row {
          Text($post.title)
          like: Button(label: "Like") { on click: Like(id: $post.id) }
        }
      }
    }
  }
}
```

Canonical example: `examples/feed-view.gr`.

### Acceptance

```bash
cargo test -p grapheme-sdk feed_view_if_for_expands_after_load

grapheme compile examples/feed-view.gr --emit view-ir --json
grapheme session examples/feed-view.gr --mount
grapheme session examples/feed-view.gr --mount --action 'expose:LoadFeed'
grapheme session examples/feed-view.gr --mount --action 'expose:LoadFeed' --render FeedView
```

Build the CLI first if `grapheme` is not on `PATH`: `cargo build -p grapheme-cli` (binary at `target/debug/grapheme`).

Expected behavior:

- `view-ir` output includes `$if` nodes under `FeedView` (compile-time shape).
- Idle `--mount` exposes `LoadFeed`; no per-post `Like` actions yet.
- After `expose:LoadFeed`, actions include two `Like` bindings with `id` bound from each post row.
- `--render FeedView` after load shows expanded rows (runtime tree, not compile-time `$for` stubs).
